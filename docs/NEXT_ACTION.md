# Единственное следующее действие — воспроизвести несовместимость Windows viewer (LAB-033)

**Почему:** пользователь уже фактически проверил первоначальную цель «посмотреть лабораторию» и обнаружил, что **официальная страница не открывается**. При `python3` 3.11.9 на Windows оригинальный `g24.demo` выполнил `PASS_DEMO` на genuine WISDM raw; `python3 -m visual_lab.build` отверг `1600_A_alpha_0/masks.csv`. Диагностика пользователя: `g24/provenance.json.files_sha256` хранит Windows ключи `1600_A_alpha_0\\masks.csv`, в то время как viewer требует `1600_A_alpha_0/masks.csv`. **4/4 outputs CSV SHA равны frozen эталонам; 3/3 PNG SHA отличаются** от pinned Linux renderer. Это подтверждённый cross-platform compatibility gap в viewer, а не доказанная ошибка G2.4 детектора. Статический HTML-предпросмотр пользователя не удовлетворяет требованию интерактивности.

**Ровно один следующий минимальный проверяемый шаг:** инженерный read-only reproduction report с точными версиями Windows/Python/NumPy/Matplotlib, original `PASS_DEMO`, actual `provenance.files_sha256` keys, independently computed SHA results четырех CSV и трёх PNG, exit code и текст `REJECTED_INPUT` по viewer. Не менять исходные `g24` outputs, WISDM raw или SHA. После reproduction отдельным решением разрешить узкий Windows portability PR и независимый audit 05; **не объявлять viewer Windows GO**, не выключать trust boundary и не пересчитывать pinned SHA ради успешного запуска.

**Проверенный baseline:** G1/G2.2/G2.3/G2.4 технические GO. Linux presentation-only viewer GO после [05 delta audit](https://github.com/kr13t1/ts-reliability-lab/issues/25#issuecomment-6628348140) на `db4b124f4e320ec273ec0322139520eefbfa7ec4`; PNG byte-pins зависят от renderer. Full G2 NOT GO, G3 CLOSED, G4 ограниченный scout, G5/G6 не открыты. Новые научные алгоритмы сейчас не создаются.
