**Проект C:** `kr13t1/ts-reliability-lab`; нормативная база — устав и `docs/PROJECT_STATE.md`, `docs/DECISIONS.md`.
**Последнее решение:** LAB-024 (2026-11-04): G1 GO, G2.2 технический GO и merged PR #8, G2.3 implementation PR #13 ожидает независимого аудита 05; полный G2 NOT GO, G3–G6 не открыты. Сверять с актуальным `docs/PROJECT_STATE.md`.
**Следующая одна задача:** [GitHub Issue #14](https://github.com/kr13t1/ts-reliability-lab/issues/14) — независимый аудит фиксированного SHA PR #13 `ac5eed80e169d153b94b5d92ffac38e820e8bed7`. Нельзя одновременно выступать автором G2.3 и его независимым аудитором.

## Что автоматизируем

В одной сессии **ChatGPT Work** координатор может читать GitHub, искать источники, создавать небольшие проверяемые артефакты, тестировать код в доступной среде, открывать Issues и PR, сопоставлять результаты с уставом и готовить решения. Рутина не требует ручного пересылания ZIP.

**Не заявлять, что Work физически общается с другими существующими чатами ChatGPT или работает бесконечно без запуска:** чаты и Work-сессии не являются общей шиной сообщений. GitHub — источник истины, GitHub Issue/PR — канал передачи.

## Порядок одной рабочей итерации

1. Прочитать Charter, актуальные `PROJECT_STATE.md`, `DECISIONS.md`, `NEXT_ACTION.md` и **один** активный Issue. Запомнить base SHA.
2. Выполнить ровно утверждённую задачу; проверять исходники, вычисления и происхождение. Не выбирать хороший seed и не смотреть test для решений об алгоритме.
3. Создать отдельную `work/<task>` ветку, маленький коммит и PR с тестами, ссылками, воспроизведением и явными UNKNOWN. Не выдавать неисполненное за PASS.
4. Для существенного кода, новых метрик, критических исправлений, переходов G2/G3/G4/G5/G6 запросить **отдельную независимую проверку** (специализированная reviewer-сессия или ветка 05, проверяющая точный SHA; один исполнитель не должен сам объявлять своё ревью независимым).
5. Координатор читает аудит, оформляет `GO/CONDITIONAL GO/NO-GO` только по названному checkpoint и записывает в журнал. Merge — лишь после решения 00.
6. Создать один следующий Issue и указать ссылки на source/PR/SHA. Дальше работать по одному ticket, не выдумывать календарные дедлайны.

## Какие решения остаются за человеком

- Выбор/смена предметной области и исследовательского направления; отказ от направления.
- Принятие темы ВКР, научного вклада, публикации/публичного раскрытия.
- Разрешение ресурсоёмких, платных, приватных или внешних действий.
- Финальное подтверждение важного gate после независимого аудита.

Обнаруженные ошибки, невозможность воспроизведения, отсутствие источника, неизвестные единицы времени — **полноценные отрицательные результаты**, а не повод автоматически подбирать другую гипотезу.

## Технические ограничения

- Приложение GitHub (подключённое к ChatGPT) может читать/писать разрешённые репозитории, но права и доступность отдельных действий могут меняться. Всегда проверять фактический GitHub SHA после записи.
- Исторические A/B EEG не переносить в этот репозиторий и не объявлять продолжением проекта C.
- Не помещать в GitHub большой сырой UCI ZIP, личные пути/секреты, доступы или приватные записи. Сохранять URL, license, checksum и короткие проверяемые отчёты.
- Автоматические тесты GitHub Actions полезны, но не равны независимому научному аудиту.
- Нельзя утверждать, что ordinary ChatGPT продолжит исследование после завершения сообщения; многосессионный автономный цикл требует поддерживаемого Work/агентного запуска.
