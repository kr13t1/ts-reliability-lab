# GitHub как один источник файлов, решений и аудита

## Разделение ролей

Это **один новый репозиторий** для проекта C. Историческое направление EEG A/B остаётся отдельно (например, `misis_article_eeg`). Чаты ChatGPT 00/01/02/03/04/05/06 — это **роли обсуждения**, а не автоматические Git-ветки.

- `main` — только принятые координатором документы и аудированные версии кода.
- `work/g2-timestamps` — рабочая ветка для проверки времени; не сливать без review 00 и при необходимости 05.
- `feature/<goal>` — реализация по фиксированной спецификации, например будущие функции G3.
- `audit/<stage>` — независимый отчёт; аудитор НЕ исправляет исходную реализацию.

## Одно действие вместо ручной пересылки ZIP

1. Участник обновляет исходные файлы **в GitHub** (commit/PR); указывает commit SHA.
2. В соответствующем чате достаточно **ссылки на GitHub commit/PR** или точного пути и SHA; подключённый GitHub даёт возможность прочитать эти файлы. Не прикладывать архивы повторно.
3. Аудитор (05) проверяет **фиксированный commit SHA**, воспроизводит тесты и публикует `docs/audits/G2_RAW_AUDIT_05.md` либо отдельный PR/комментарий.
4. Координатор (00) принимает решение и обновляет `docs/PROJECT_STATE.md` + `docs/DECISIONS.md` в `main`. Исторические решения не переписывать.
5. Большие raw-наборы остаются локально. В репозитории — код загрузки, URL, лицензии, SHA-256, проверенные небольшие metadata и графики/CSV экспериментов.

## Текущие ограничения

На момент подготовки шаблона новый GitHub-репозиторий ещё не создан. Проверен доступ подключённой учётной записи к старому EEG-репозиторию, **новая лаборатория туда не отправлялась**. Первый коммит и GitHub URL будут известны только после создания нового репозитория.

## Как загрузить этот шаблон на Windows (после создания ПУСТОГО private repo)

Открой PowerShell **в корне распакованной папки** с `README.md`:

```powershell
git --version
git init -b main
git add .
git status
git commit -m "chore: initialize audited reliability lab"
git remote add origin https://github.com/<YOUR_LOGIN>/ts-reliability-lab.git
git push -u origin main
```

Замени `<YOUR_LOGIN>` своим логином. Команды запуска G1 — в корневом `README.md`. Для GitHub push нужна аутентификация (обычно Git Credential Manager); пароли и токены в чат не присылай.

Если Git ещё не установлен, можно создать пустой приватный репозиторий через GitHub, прислать **его URL** в чат 00 и затем работать с подключённым GitHub-инструментом по мере доступности операций.
