## Главная идея проекта C

Изучаем надёжность многоканальных временных рядов наблюдений, а не обязательно «неисправности смартфона». Используем проверяемые контролируемые вмешательства, чтобы знать `X_ref`, `X_obs`, назначенную маску `Z`, и честно сравнивать детекцию, восстановление и последствия для последующей модели. **Эти три задачи раздельны.** Реальный `X_ref` может уже содержать природные артефакты. Ни один из показателей G2.3 не измеряет качество обнаружения или восстановления: `D_I=3.0753845` является величиной ВНЕСЁННОГО изменения.

### Выход 1 — воспроизводимая лаборатория и статья на Хабре

**Аудитория:** инженер, ML-специалист, студент. **Обещанный продукт:** локальный runnable Python-проект с графиками reference → artificially corrupted → mask; потом прозрачный detector baseline, простой repair baseline и fixed downstream classifier; интерактивный просмотр только после CLI/тестов. Нормальный сценарий: исходное изменение по оси видно; отрицательный: неподвижный датчик или идентичные значения провоцируют ложные срабатывания.

**Требование публикационной готовности:** один проверенный PR/релиз, команды, исходный датасет/лицензия, seed/конфиг, точные метрики, отказ/негативные случаи и 05 GO на публикуемые результаты. Честно написать «искусственная инъекция»; не говорить «обнаружены реальные поломки» и «новый метод». Можно подготовить структуру статьи заранее, **не** писать якобы выполненные будущие эксперименты. Хабр не тождественен научной рецензируемой статье и **без отдельного требования кафедры не считается автоматически зачётной публикацией**.

### Выход 2 — одна научная публикация по отдельному архиву A/B

**Исследовательские следы:** (A) MI EEG: μ/β bandpower, HFD, их комбинация — исторический результат test balanced accuracy 0.8500 / 0.7857 / 0.842857 на одном Graz subject; улучшение от добавления HFD **не подтверждено**. (B) HFD–U1: методологическая конечновыборочная вариабельность HFD, синтетические зависимые модели/Monte-Carlo/block-bootstrap, ранее полученное условное/ограниченное решение по численным результатам; это **не** доказанная новизна статистического метода и **не** результат на реальном MI EEG. Исторические сведения из прежних исследовательских чатов, **не прошли новый аудит в проекте C**.

**Не делать:** переносить исходники A/B в новый GitHub, смешивать STORM/WISDM со старой EEG статьёй ради «вклада», менять тему HFD-classification на HFD–U1 без 00, выдавать отрицательную разность за улучшение, отправлять сырой manuscript без отдельного научного prior-art и корректной статистики.

**Путь:** отдельно подтвердить архив и результатный аудит выбранной A **или** B, проверить ближайшие статьи 2023–2026 и требования реального издания; 00 выбирает один материал и публикационную границу; редактор пишет IMRAD только из этих данных. **Научная публикация по C сейчас не обоснована**; возможно позже после G4/G5, но обещать её как обязательный результат C нельзя.

### Выход 3 — НИР-7 и будущая ВКР

**Официальная основа, действительно прочитанная:** PDF `Требования по НИР (бак. 7-й сем. у.г. 2025-2026).pdf` кафедры инженерной кибернетики НИТУ «МИСИС», направление 01.03.04 прикладная математика, **документ именно для 2025–2026 уч. года**, сохранён в ранее загруженных пользовательских материалах, **не** в этом GitHub. Для 2026–2027 применимость/новые сроки **НЕ ПОДТВЕРЖДЕНЫ**; не придумывать новые дедлайны или требования к публикации.

Проверенные нормы страниц 19–24, 32–36:
- рекомендуемый объём 25–35 страниц, не менее 20, без титульного листа и приложений; русский язык;
- введение 1–1,5 стр.; обзор 15–20 стр. и **не менее 10** библиографических источников, из них **не менее трёх печатных на иностранных языках** по основной тематике, ограничения прямых цитат;
- обязательные главы: титульный, содержание, сокращения, введение, аналитический обзор, содержательная постановка, математическая постановка, выбранный математический аппарат, программно-алгоритмическая часть, проведённые исследования и анализ, выводы, источники; документ разрешает обоснованное объединение некоторых соседних разделов;
- выводы 3/4–1,5 стр., доклад на защите до 7 минут с презентацией; официальное допущение к защите руководителем по документу;
- формальное оформление в соответствии с упомянутым в требованиях нормоконтролем (методичка Бабичев/Баранникова 2018, предоставленный файл `Рекомендации-Нормоконтроль-ВКР-2019.pdf` проверять отдельно).

**Как НИР связать с текущей лабораторией, не подменяя ВКР:** рабочая/предварительная область — «Контролируемое моделирование нарушений качества многоканальных измерительных временных рядов и оценка базовых алгоритмов». Это **название для черновика**, не утверждение темы научным руководителем. Отчёт может включать устав, обзор типов отказов, математику `X_ref, C, X_obs, Z`, описание verified G1/G2 и честный результат G2.3 *только после 05*, ограничения данных, план проверки простых baseline. В нём должны быть **реально проведённые исследования** и анализ, а не только схема будущей ВКР. Пример NIR не является доказательством новизны.

**Готовность НИР-7:** (а) подтверждён актуальный факультетский регламент/руководитель; (б) 10+ проверенных работ и 3+ иностранных печатных по теме, а не только произвольные веб-ссылки; (в) строгая постановка, корректная метрика и реально выполненная программа/эксперименты; (г) аккуратные таблицы/рисунки, результаты с provenance; (д) текст и короткая презентация. Сценарий «НИР как подготовка ВКР» не позволяет заранее объявлять выбранную научную новизну.

1. **СЕЙЧАС:** независимый 05 аудит PR #13 на fixed SHA. Ни один другой инженерный сценарий не утверждать до этого.
2. **После 05:** 00 принимает/возвращает G2.3; при GO — merge одного PR и запись LAB-действия.

Только при подготовленном контроле WISDM subjects/sessions.
4. **Далее:** закрыть нужные данные/splits, затем G3 сравнительная карта detection vs repair vs selective reliability. Базовые показатели: event/point precision/recall/FP, RMSE repair на Z, balanced accuracy (fixed split), risk–coverage. Нельзя смешивать эти метрики.
5. **Отдельно:** ограниченный literature G4 по конкретному слабому месту baseline (после реальных false positives/false negatives), выбор G5 только после проверки prior-art.
