## 2. Правила декодирования и способ выбора

Каждая физическая строка исходного TXT без заголовка имеет вид `subject_id,activity_code,q,x,y,z;`. В этой проверке:
- UTF-8/ASCII; ровно шесть непустых полей через пять запятых, один заключительный `;`; `subject_id`, `q` проверены как **целые десятичные**.
- `x,y,z` прочитаны из исходных десятичных **токенов без изменения записи**, каждый дополнительно строго разобран в `Decimal`, проверено `is_finite()`; **никакой** нормализации, округления, фильтрации или изменения координат.
- Выделены *максимальные contiguous* серии равного `(subject_id, activity_code)` в **первоначальном порядке физических строк**; выбор **первой E-серии 1600** определён заранее Issue #18, без осмотра выходов детектора.
- `q` оставлены исходными integer без деления на `10^n`, ns/Hz/UTC/epoch; внутри серии проверено `q[i+1] > q[i]`. Сравнение `q` на стыках серий не служит ни сортировкой, ни доказательством непрерывного сеанса.

## 4. Что означает «неповреждённый» здесь

**CONFIRMED по происхождению текущей обработки:** это непосредственные байты исходного транспортированного raw WISDM TXT; **проектный оператор freeze не вызывался, никакие инъекции не назначались**, `X_obs = X_ref` только в смысле **отсутствия нашего вмешательства**. Если формально требуется маска **назначенной проектной инъекции**, она **вся нулевая: `Z=0`** по определению контроля, **не извлечена из колонок UCI** и не является внешней меткой неисправностей.

**UNKNOWN:** были ли естественные аппаратные ошибки/плоские участки или потери исходных отсчётов, физическая исправность телефона, наличие независимого `session_id`, абсолютная единица/эпоха `q`, реальная хронология всех 18 блоков, полный удалённый checksum UCI. Этот блок — **negative control относительно отсутствия искусственной инъекции**, но **не proven-clean sensor negative**.

**Контроль независимости:** 1600/A и 1600/E — два разных последовательных блока **того же subject_id=1600**, а не доказанные независимые физические сессии. Никаких train/test разбиений, статистических повторов из 3572 строк и claims о независимых людях.

## 5. Минимальное воспроизведение без изменения данных

Сохранить следующий **проверочный код вне исходного репозитория** как `verify_standing_readonly.py`, затем вызвать `python verify_standing_readonly.py "путь/к/G2_RAW_FOR_AUDIT_05.zip"`. Код только читает ZIP, ничего не записывает, не использует `g2/readonly.py` или алгоритм детектора.

```python
import hashlib, re, sys, zipfile
from decimal import Decimal
from pathlib import Path

p = Path(sys.argv[1])
def h(b): return hashlib.sha256(b).hexdigest()
before = h(p.read_bytes())
with zipfile.ZipFile(p) as z:
    assert z.testzip() is None
    raw = z.read("data_1600_accel_phone.txt")
    key = z.read("activity_key.txt")
assert before == "7aca931a3af368bae0ac932140aff270f9cd5f0c6c783e393c83c1672628f503"
assert h(raw) == "40b7f60880b495ccb3c345b9ab11216dfa6bbb2bb887bcb45fb55020278fc22f"
assert len(raw) == 3451789
assert b"standing = e" in key.lower()
lines = raw.splitlines(keepends=True)
assert len(lines) == 64311
rows, offset = [], 0
for line_no, raw_line in enumerate(lines, 1):
    s = raw_line.rstrip(b"\r\n").decode("ascii")
    assert s.endswith(";") and s.count(";") == 1
    f = s[:-1].split(",")
    assert len(f) == 6 and all(f)
    assert re.fullmatch(r"[0-9]+", f[0]) and re.fullmatch(r"[0-9]+", f[2])
    assert re.fullmatch(r"[A-Z]", f[1]) and f[0] == "1600"
    assert all(Decimal(x).is_finite() for x in f[3:6])
    rows.append((line_no, f, offset, offset + len(raw_line)))
    offset += len(raw_line)
runs, start = [], 0
for j in range(1, len(rows) + 1):
    if j == len(rows) or rows[j][1][1] != rows[start][1][1]:
        runs.append((start + 1, j, rows[start][1][1]))
        start = j
assert len(runs) == 18
assert [x for x in runs if x[2] == "E"] == [(14292, 17863, "E")]
assert (rows[14290][1][1], rows[17863][1][1]) == ("D", "F")
E = rows[14291:17863]
q = [int(r[1][2]) for r in E]
assert len(E) == 3572 and q == sorted(set(q))
assert (q[0], q[-1]) == (241892286783982, 242072100924919)
segment = raw[E[0][2]:E[-1][3]]
assert h(segment) == "50edfd731735d54cd76fe4c0a38da914fca7b567ae4e3b3d389f2d687fadb61d"
assert h(p.read_bytes()) == before
print("PASS_RAW_STANDING_E", "N=", len(E), "q_first=", q[0], "q_last=", q[-1])
print("raw_sha256=", h(raw), "segment_sha256=", h(segment))
```

**Проверено в данном read-only проходе:** SHA транспорта/исходного TXT/отрезка, все 64 311 строк и декодирование, границы, соседние коды, 3572 `q`, значения `x/y/z` и независимость исходных данных от наших инъекций. Первоначальный запуск внутреннего контрольного скрипта остановился на регистре буквы E в проверке `activity_key` (`key.lower()`); исправлена только проверка в **отдельном** скрипте, исходный архив не менялся. Финальный полный прогон **PASS**.

## 6. Передача и границы решения

**Результат ветки 02:** `READY_FOR_00_REVIEW` только по **read-only входному Standing/E 1600**. Действующий G2.3 Walking/A freeze — отдельная принятая демонстрация, не часть этого контроля. Здесь **не запускались** constant-run detector, `Zhat`, TP/FP/FN/TN, recall, quality metrics, графики, подбор L, repair, ML, окна, splitting или resampling.

**Один следующий организационный шаг:** передать настоящий отчёт **00** на проверку; только 00 вправе принять/отклонить input gate и отдельно разрешить ограниченный G2.4. До такого разрешения baseline A **не исполнять**. Full G2 NOT GO; G3 CLOSED; отсутствие научной новизны не пересматривается.
