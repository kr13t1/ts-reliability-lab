## 3. Объект и точная адресация

Источник — неизменённые байты member
`wisdm-dataset/raw/phone/accel/data_<subject>_accel_phone.txt`.
Допустимые subject ID — только 1600, 1601, 1602; activity — A, E.

Строка имеет схему `subject_id,activity_code,timestamp,x,y,z;`. Номер физической строки L начинается с 1. Конечный перевод строки не создаёт дополнительную запись. Пустая строка внутри файла не пропускается молча. Допускаются LF/CRLF и окружающие пробелы полей; исходные байты сохраняются, ровно шесть непустых полей и один завершающий `;` обязательны. Subject и q разбираются непосредственно как десятичные целые; q никогда не проходит через float. x,y,z — конечные десятичные числа, сохраняемые также исходными токенами и в float64; NaN/Inf/неразбираемое значение — ошибка.

Run [L_start,L_end] — максимальный непустой интервал соседних физических строк с постоянными subject и activity. Он строится в порядке файла, **до** фильтрации A/E. Нельзя сначала выбрать все A и склеить их через B. Изменение кода, файла или subject — граница; невалидная строка блокирует запуск, а не исчезает при разборе. Сброс q внутри выбранного run — основание отказа, не повод автоматически отсечь часть или переставить строки.

Пусть N=L_end−L_start+1, i=0,…,N−1, L(i)=L_start+i. Определим

- X_ref ∈ R^(3×N), X_ref[:,i]=(x_L(i),y_L(i),z_L(i));
- q_i — исходное целое третьего поля строки L(i);
- Δq_i=q_(i+1)−q_i, i=0,…,N−2, в целых единицах файла;
- y — опубликованный activity-code всего run, без предсказаний;
- идентификатор записи: (raw SHA-256, member path, subject, activity, L_start, L_end).

X_ref — наблюдаемая опорная запись с возможными исходными ошибками. Амплитуда подписывается «м/с² по документации WISDM», без заявления о независимой калибровке. Индекс не является равномерной физической шкалой времени. Строгое Δq>0 удостоверяет только порядок целых q; не отсутствие физических разрывов. Единица демонстрации — один run, не N независимых наблюдений; статистического размера выборки и доверительных интервалов здесь нет.

## 5. Выход одного будущего read-only запуска

В отдельном каталоге результатов (не внутри G1/raw):

1. `config.json`: версия контракта и точный утверждённый SHA, input/member/SHA, правило выбора, ожидаемые границы, `mode=reference_only`, `timestamp_unit=UNKNOWN`, `session_id=null`, `seed=null` (случайных операций нет).
2. `reference.csv`: ровно N строк, колонки `i,source_line,subject,activity,q,x,y,z`; q — десятичный текст без экспоненты, x/y/z — исходные числовые токены. Сохранить числа без редукции точности; никаких электронных таблиц с автоматическим float-преобразованием q.
3. `selection.json`: полный input SHA/размер/строки, выбранные границы, коды соседей или null на краю файла, N, q endpoints, число/min/median/max Δq, сумма Δq; q и все Δq сериализуются десятичными строками для защиты от потерь в сторонних JSON-клиентах.
4. `reference.png`: три панели x/y/z, все N точек по i=0,…,N−1, без сглаживания/децимации, с подписями source lines и subject/activity. Соединяющая линия — только визуальная связь соседних строк, не реконструкция физического пути. Нет оси секунд/Гц, маски «реальных fault», предсказаний или утверждений о чистоте.
5. `validation.json` и `provenance.json`: реально выполненные проверки/ошибки, команда, версии Python/зависимостей, implementation SHA и dirty flag, входные и выходные SHA-256, атрибуция, `physical_continuity=UNKNOWN`, `full_remote_attestation=UNVERIFIED`. Хеши выходов хранить в provenance без самохеширования этого файла; raw не коммитить в GitHub.
6. Короткий отчёт с командой воспроизведения и фактическим результатом. При отказе — только конфигурация и отчёт отказа с доступными provenance, без успешного графика или выдуманных метрик.

Проверки целых, строк и хешей — точное равенство. Повторный разбор CSV в том же float64-окружении должен дать те же X_ref; исходные токены обеспечивают дополнительную проверку без float. Изменяемые метаданные запуска исключать из сравнения численных результатов. Побайтовая идентичность PNG между платформами не требуется; сравниваются изображённые массивы, подписи и диапазоны, график проверяется визуально.

## 6. Критерии приёмки и опровержения

Будущая иллюстрация считается технически воспроизведённой только если независимый исполнитель на тех же raw-байтах и утверждённом implementation SHA получает ту же запись, N, соответствие каждой строки и целые q, а исходные raw/G1 неизменны. Совпадение одного только скриншота недостаточно.

| Планируемая проверка (сейчас НЕ запущена) | Ожидаемое поведение |
|---|---|
| Выбор по закреплённому перечню | Единственный результат 1600/A, 1–3574 |
| A,B,A в искусственной фикстуре | Два отдельных A-run; склейка запрещена |
| Равные или убывающие q внутри выбранного run | Отказ без сортировки/обрезки |
| Очень большой положительный Δq | Сохранение значения, без вывода о fault/потерях |
| Пустая/испорченная строка, NaN/Inf, чужой subject | Отказ без молчаливого удаления |
| q за пределами точного float64 integer | Точный integer round-trip или явный отказ неподдерживаемого представления; никогда округление |
| Иной SHA, отсутствующий raw, несоответствие таблице | Соответствующий BLOCKED/REJECTED, без fallback |
| Изменена только амплитуда фикстуры при тех же метаданных | Правило адресного выбора не меняется; для реального входа смена SHA блокирует запуск |
| Повторный запуск фиксированного входа | Те же CSV-токены, границы, q и численные массивы |

Нарушение хотя бы одного инварианта опровергает корректность **реализации контракта**. Оно не доказывает неисправность сенсора. Невидимый на графике ритм ходьбы, необычная форма или отсутствие желаемого эффекта не являются поводом подбирать другую запись. Гипотезы H0/H1 об эффективности, p-values и bootstrap здесь неприменимы: нет сравнения независимых выборок.

## 7. Неактивное предложение будущей контролируемой инъекции

**Не входит в первый запуск. Требует отдельного явного решения 00.** Формулы нужны для проверки смыслов маски и метрик, не для открытия G3.

Для той же неизменной полной записи предлагается один freeze-оператор оси x (c=0), a=floor(N/3), b=floor(2N/3), полуинтервал I=[a,b), 1≤a<b<N; при N=3574: a=1191, b=2382, длина 1191. Ни один интервал не является обучающим окном. Два заранее заданных режима α∈{0,1}, без случайности:

X_obs[c,i]=(1−α)X_ref[c,i]+αX_ref[c,a−1] при c=0 и a≤i<b; иначе X_obs[c,i]=X_ref[c,i].

Z[c,i]=1 тогда и только тогда, когда α=1, c=0 и a≤i<b. При α=0 вся Z=0. Z — **область назначенной инъекции**, не индикатор неравенства чисел и не маска естественных неисправностей. Если исходная ось на I уже равна удерживаемому значению, Z=1 на I, хотя численный эффект равен нулю; это допустимый нулевой результат.

Единственный контрольный baseline — тождественная обработка R_id(X_obs)=X_obs («не обрабатывать»). Это не детектор, не восстановление и не классификатор. Предлагаемые описательные метрики:

- D_I = sqrt[(1/(b−a)) Σ_(i=a)^(b−1) (X_obs[0,i]−X_ref[0,i])²] — изменение оси x на заранее заданном I.
- D_Z = sqrt[(1/|Z|) Σ_(c,i:Z[c,i]=1) (R_id(X_obs)[c,i]−X_ref[c,i])²], где |Z|=Σ Z. При |Z|=0: значение null, статус NOT_APPLICABLE, не 0/0 и не выдуманный ноль.
- L_out = max_(c,i:Z[c,i]=0) |X_obs[c,i]−X_ref[c,i]| — отсутствие побочных изменений; дополнительно требуется точная поэлементная идентичность вне Z.
- n_assigned=|Z| и n_changed=Σ 1{X_obs≠X_ref} сохраняются отдельно.

При α=0: X_obs=X_ref, D_I=0, D_Z=null, L_out=0, n_assigned=n_changed=0.
При α=1: n_assigned=1191, n_changed≤1191, D_Z=D_I≥0, L_out=0; D_I может быть нулём. Деление на 3N вместо b−a для этих метрик недопустимо. Размерность D — амплитуда (м/с² по документации), не время и не точность модели.

При последующем отдельном разрешении сохранять config, X_ref/X_obs/Z, results.csv, график и provenance для обоих α, включая нулевой эффект. Эти параметры не подбираются по результату. Сравнение относится только к искусственно внесённому изменению одной наблюдаемой записи, не к качеству восстановления физического сигнала. Порог успеха «ошибка обязана вырасти/модель обязана ошибиться» отсутствует.
